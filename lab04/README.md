## Таблица значений для суммирования чисел 1–4

Фрагмент из `example.py`:

```python
total = 0
for number in range(1, 5):
    total += number
    print(f"Число: {number}; сумма: {total}")
```

| Итерация | `number` до | `total` до | `total` после |
| --- | --- | --- | --- |
| 1 | 1 | 0 | 1 |
| 2 | 2 | 1 | 3 |
| 3 | 3 | 3 | 6 |
| 4 | 4 | 6 | 10 |

## Пояснения

- **`for` и `while`:** `for` перебирает готовую последовательность (`range`), `while` выполняется, пока условие истинно. В `while` значение, участвующее в условии, должно изменяться в теле, иначе цикл бесконечный.
- **Почему цикл завершится:** в `positive_input.py` при каждом отказе запрашивается новое число, и рано или поздно пользователь введёт положительное. В `prime.py` переменная `divisor` увеличивается на 1 каждую итерацию, а условие `divisor * divisor <= n` рано или поздно станет ложным.
- **`range(a, b)` не всегда подходит для задания №1:** `range(a, b)` идёт только по возрастанию и не включает `b`. При `a > b` нужен `range(a, b - 1, -1)`, а при `a == b` цикл вообще не выполнится - нужно обработать равенство отдельно.
- **Инициализация максимума:** нельзя начинать с нуля — при всех отрицательных числах ответ будет неверным. Правильно инициализировать первым введённым значением.
- **`break`:** в `prime.py` прерывает цикл, как только найден делитель, - дальше проверять нет смысла.
- **Ноль кратен любому ненулевому целому:** поэтому в вариантах с условием «кратные» ноль учитывается.
- **Сложность проверки простоты:** перебор делителей до `sqrt(n)` даёт порядка `sqrt(n)` проверок в худшем случае. Рекурсия сама по себе не делает алгоритм логарифмическим.
